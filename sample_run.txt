## 🏆 Best Issue to Tackle: #30667 — Memory Leak in `RunnableSequence`

**"core: leak when using object member in a `RunnableSequence`"**
🔗 https://github.com/langchain-ai/langchain/issues/30667
Labels: `help wanted`, `bug`, `core`

**Why it's perfect for you:**
- ✅ **Unassigned** — no one currently owns it, so you won't duplicate effort
- ✅ **Root cause already identified** by the community: an `@lru_cache` on `get_function_nonlocals` holds strong references to bound methods, preventing garbage collection
- ✅ **Clear fix direction**: Replace `@lru_cache` with a `weakref`-based cache (e.g., `WeakKeyDictionary`) — several commenters have confirmed this works
- ✅ **High impact**: A previous contributor's prototype PR (#35797) showed a **+30.89% performance improvement** on CodSpeed benchmarks
- ✅ **Scope is manageable**: The fix is localized to `libs/core/langchain_core/runnables/utils.py` (around the `get_function_nonlocals` function)
- ✅ **No external API keys required** — pure Python/core change, easy to test locally

**Your path forward:**
1. Comment on #30667 asking to be assigned (the repo CI bot requires assignment before a PR is opened)
2. Locate `get_function_nonlocals` in `libs/core/langchain_core/runnables/utils.py`
3. Replace `@lru_cache` with a `WeakKeyDictionary`-based cache, handling the edge case that bound methods can't be directly weakly referenced
4. Run the GC reproduction script from the issue body to verify the fix
5. Open a PR linked to the issue
